═══════════════════════════════════════════════════════════════════════════════
 FASE 1 — SMOKE TEST DO WORKER (5 min)
 Objetivo: provar que o worker do L2CS carrega sem crash antes de calibrar
═══════════════════════════════════════════════════════════════════════════════

1.1  Reinicie o dev server para pegar as últimas mudanças de código:
       Ctrl+C no terminal do dev
       npm --prefix frontend run dev

1.2  Abra http://localhost:5173 no browser.
     Abra DevTools (F12) → aba Console.

1.3  No console, ligue a flag:
       localStorage.setItem('l2cs.enabled','true'); location.reload();

1.4  Passe pela permissão de câmera normalmente.
     Aguarde ~5-10 segundos (o ONNX de 91 MB precisa baixar).

1.5  Procure no console:
       [L2CS] worker ready
       [IrisFlow] engine stats — frames=... l2cs=ready submit=N valid=N stale=N

     Checklist:
       [ ] "[L2CS] worker ready" apareceu
       [ ] Stats contém "l2cs=ready" (NÃO "l2cs=off")
       [ ] "submit" cresce a cada 3 s (worker aceitando frames)
       [ ] "valid" cresce (worker produzindo resultados)
       [ ] Cursor gaze se move sem travamentos perceptíveis

1.6  Se algo falhar:
       - "worker init failed" → aba Network, procure se os arquivos
         .wasm/.mjs (ort-wasm-simd-threaded-*.wasm e .mjs) retornaram 200
       - "l2cs=off" persistente após 15s → worker crashou;
         DevTools → Sources → aba Workers para stack trace
       - Cursor travou → CPU sobrecarregada; verificar que outros processos
         pesados (call de vídeo, etc.) estão fechados

     ► Se o smoke passou, prossiga. Se falhou, resolva antes de ir adiante.

═══════════════════════════════════════════════════════════════════════════════
 FASE 6 — INVESTIGAÇÃO (só se veredicto for = ou ✗)
 Objetivo: encontrar qual das falhas silenciosas do §6 disparou
═══════════════════════════════════════════════════════════════════════════════

Suspeitos ordenados por probabilidade e ordem de investigação:

6.1  ══ Sinal do pitch invertido (5 min) ══
     Sintoma: L2CS piora em Y mas não em X, ou vice-versa.
     Teste: tire uma foto extra "look_down" (olhando pra parte de baixo do
            monitor) usando http://localhost:5173/l2cs_capture.html.
            Salve em frontend/python_scripts/l2cs_validation/look_down.jpg
            e rode:
              node frontend/scripts/l2cs_axis_validation.mjs

     Se o script apontar sinal invertido do pitch:
       Editar src/l2cs/block.ts, na função buildL2CSBlock, negar `p`:
         const p = -clamp(pitch, -CLAMP_RAD, CLAMP_RAD);
       Rebuild, recalibrar, refazer A/B.

6.2  ══ EXPAND_FACTOR fora da convenção (30-60 min) ══
     Sintoma: L2CS empata ou piora consistentemente, sem viés em nenhum eixo.
     Ação: varrer valores em src/l2cs/crop.ts:
       Trocar EXPAND_FACTOR entre [1.0, 1.2, 1.4, 1.6, 1.8] uma de cada vez.
       Para cada valor, rebuild + calibrar + rodar accuracy test.
       Salvar l2cs.json de cada rodada como l2cs_ef1.0.json, l2cs_ef1.2.json etc.
       Comparar com baseline.json usando l2cs_ab_compare.mjs.
       Fixar o valor que der o menor meanError.

6.3  ══ BGR/RGB trocado ══
     Sintoma: ângulos coerentes na direção mas com bias grande.
     Teste: rodar axis_validation e conferir se look_center dá (~0, ~0).
       Se der offset grande e sistemático, editar
       src/l2cs/crop.ts::preprocess448FromRGBA — trocar índices R e B.
       (Improvável — Canvas 2D sempre entrega RGBA em ordem, mas verificar.)

6.4  ══ Ordem yaw/pitch trocada ══
     Sintoma: L2CS piora fortemente em ambos eixos.
     Teste: rodar axis_validation. Se look_right mexer principalmente PITCH
            (em vez de yaw), o export trocou os nomes.
     Fix: editar frontend/public/models/l2cs/l2cs.meta.json:
       Trocar "outputTensorNames": { "yaw": "pitch", "pitch": "yaw" }

6.5  ══ Fórmula de decodificação (Gaze360 vs MPIIGaze) ══
     Sintoma: ângulos absurdos (ex. 90° com rosto reto).
     Teste: axis_validation com look_center deve dar |yaw|,|pitch| < 15°.
     Se der 100°+, está usando fórmula errada. Trocar no meta.json:
       Gaze360 = { bins:90, binWidth:4, binOffset:-180 }
       MPIIGaze = { bins:28, binWidth:3, binOffset:-42 } (aprox.)

Após cada correção: rebuild + recalibrar + refazer FASE 4.

═══════════════════════════════════════════════════════════════════════════════
 REFERÊNCIAS RÁPIDAS
═══════════════════════════════════════════════════════════════════════════════

Comandos do console DevTools:
  Ver flag atual:      localStorage.getItem('l2cs.enabled')
  Ligar L2CS:          localStorage.setItem('l2cs.enabled','true');  location.reload()
  Desligar L2CS:       localStorage.setItem('l2cs.enabled','false'); location.reload()
  Voltar ao default:   localStorage.removeItem('l2cs.enabled');       location.reload()

Sinais no console (linha [IrisFlow] engine stats):
  Sem "l2cs=..." no fim → flag OFF nessa sessão
  "l2cs=ready submit=N valid=N stale=N" → flag ON, worker rodando
  "l2cs=off submit=0"                   → flag ON mas worker falhou (checar Network)

Arquivos importantes:
  src/l2cs/flags.ts                         → default de compilação
  src/l2cs/l2cs.worker.ts                   → worker + config do ORT
  src/l2cs/crop.ts                          → EXPAND_FACTOR fica aqui
  src/l2cs/block.ts                         → sinais do bloco de 7 dims
  frontend/public/models/l2cs/              → onnx + meta.json
  frontend/scripts/l2cs_ab_compare.mjs      → script de A/B
  frontend/scripts/l2cs_axis_validation.mjs → validação de sinal/decodificação
  L2CS-NET.md                               → documento de arquitetura completo

Se algo der errado ou aparecer sintoma estranho:
  1. Salvar o output do console (Ctrl+A no console + copiar)
  2. Salvar os JSONs de accuracy relevantes
  3. Anotar o que exatamente foi feito
  → aí é possível diagnosticar sem re-rodar tudo
